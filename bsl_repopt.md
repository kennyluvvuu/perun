## 2. Ошибки

### 2.1. `bsl_fix_standards` не принимает каталог

```
[bsl_fix_standards] error: Ошибка открытия файла 'src': EISDIR: illegal operation on a directory, read
```

Вызов с `target = src` (каталог) падает: инструмент читает путь как файл, рекурсивный обход каталога не выполняется.
Расхождение с описанием инструмента: `target (string, обязательно): путь к файлу .bsl или каталогу для проверки`.

Следствие: пакетная проверка проекта одним вызовом невозможна, требуется перечислять файлы по одному.

### 2.2. Заблокирован запуск анализатора напрямую из shell

```
Вызов 'bash' заблокирован: действие не подтверждено пользователем
(Абсолютный путь '/Users/kenny/Work/pi/packages/1c-agent/bin/tools/bsl-analyzer'
 находится за пределами каталога проекта (/Users/kenny/Work/TEST-perun)).
```

Попытка вызвать бинарь анализатора по абсолютному пути из-за пределов проекта отклонена политикой путей.
Это корректное поведение политики; ошибка была моя — нужно было оставаться на встроенных инструментах, а не шеллиться наружу.

### 2.3. Класс дефекта, который инструмент принципиально не видит

Фактический дефект проекта (не найден ни одним вызовом `bsl_fix_standards`):

```
РегистрНакопления.ТоварыНаСкладах.Остатки(&МоментВремени, Склад = &Склад, Номенклатура, Количество)
```

Лишние фактические параметры у виртуальной таблицы `Остатки()` — платформа такой запрос отклоняет (исключение при `Выполнить()`),
из-за чего падали `УправлениеЗапасами.ОстаткиПоСкладу` → `ОбработкаПроведения` заказа и два отчёта на СКД.
Правила на арность параметров виртуальных таблиц в наборе нет: анализатор отдаёт только предупреждения уровня стандартов
(`QueryNestedFieldsByDot`, `JoinWithVirtualTable`), а не «платформа отклонит запрос» (как, например, `AmbiguousFieldInQuery`).

Дополнительно: текст запроса внутри шаблона СКД (`src/Reports/*/Templates/.../Ext/Template.xml`) анализатором не разбирается —
обрабатываются только `.bsl`. `skd-validate`/`skd-info` проверяют структуру схемы, но не текст запроса.

## 4. Предложения

1. `bsl_fix_standards`: поддержать `target = <каталог>` (рекурсивный обход `*.bsl`, агрегированный отчёт) — сейчас падает с `EISDIR`.
2. Добавить SDBL-правило проверки числа/типов фактических параметров виртуальных таблиц
   (`Остатки`, `Обороты`, `ОстаткиИОбороты`, `СрезПоследних` и др.) с severity Blocker.
3. Расширить разбор на тексты запросов в шаблонах СКД/отчётов (`Template.xml`, `DataCompositionSchema`), иначе дефект
   в отчёте ловится только в рантайме.
4. В описании инструмента синхронизировать заявленную поддержку каталога с фактической реализацией.
