# Контракт: документация ПерУН в плагине EDT

Здесь описано, что нужно сделать в плагине [1C_plug](https://github.com/Kronos070/1C_plug), чтобы показать пользователю единую документацию проекта. Со стороны ПерУН всё готово: база, индексация из git, поиск, запись описаний агентом и RPC-методы.

## Что получит пользователь

В шапке чата появляется кнопка «Документация». Она открывает экран из двух частей:

- **Сайдбар.** Сверху поиск. Под ним вкладки разделов: «Модули», «Процедуры», «Функции», «Переменные», «Требуют внимания». Внутри раздела дерево, как дерево файлов: «Документы → Заказ → Модуль объекта → ОбработкаПроведения». Узлы раскрываются по клику и подгружаются по мере раскрытия.
- **Страница.** Справа (на узкой панели вместо дерева) показана страница выбранного модуля или метода: сигнатура, параметры, комментарий из кода, описание, частные случаи, состав модуля. Описание можно отредактировать и сохранить.

Документация общая для всех чатов проекта и хранится у ПерУН в `~/.perun/agent/docs.db`. Структура (модули, методы, переменные) строится по последнему коммиту локального git. После нового коммита ПерУН переиндексирует только изменённые файлы. Описания пишет агент, когда объясняет код (инструмент `1c_docs_write`), или пользователь в этом экране.

## Транспорт

Плагин уже говорит с ПерУН через `perun --mode rpc`. Для документации используется одна новая команда ядра — `extension_request`:

```json
{"id": "edt-42", "type": "extension_request", "method": "docs.tree", "params": {"section": "function"}}
```

Ответ приходит в обычном формате, его уже разбирает `RpcConnection.complete()`:

```json
{"id": "edt-42", "type": "response", "command": "extension_request", "success": true, "data": {"section": "function", "node": "", "items": []}}
```

Ошибка приходит как `success: false` и `error`, например `"Документация не найдена: src/X.bsl"`. `RpcConnection` превратит её в `RpcException` с этим текстом. Покажите его пользователю как есть, тексты уже на русском.

В Java вызов выглядит так:

```java
JsonObject payload = new JsonObject();
payload.addProperty("method", "docs.tree");
payload.add("params", params);
rpc.request("extension_request", payload, true);
```

Для `docs.sync` передавайте `timed = false`: первая индексация большой конфигурации (ERP) может идти несколько минут. Остальные методы отвечают за миллисекунды, им хватает таймаута 60 секунд.

**Как понять, что ПерУН поддерживает документацию.** В ответе `get_commands`, который плагин уже запрашивает при старте, есть команда `docs`. Если её нет (старый perun или pi), кнопку в шапке не показывайте.

## Идентификаторы

У каждой страницы есть `id`:

- модуль — путь файла относительно рабочего каталога агента: `src/Documents/Заказ/ObjectModule.bsl`;
- символ — путь модуля, `#` и имя: `src/Documents/Заказ/ObjectModule.bsl#ОбработкаПроведения`.

Узлы дерева адресуются так же: папка — путь каталога (`src/Documents/Заказ`), модуль — путь файла. Пустая строка означает корень раздела. Не собирайте `id` вручную, берите их из ответов (`id`, `docId`, `module.id`, `members[].id`).

## Методы

Все параметры передаются в `params`. Необязательные можно не передавать.

| Метод | Параметры | Ответ `data` |
|---|---|---|
| `docs.status` | — | `{ status: DocsStatus }` |
| `docs.sync` | — | `{ report: DocsSyncReport, status: DocsStatus }` |
| `docs.tree` | `section`, `node?` | `{ section, node, items: DocTreeNode[], syncing }` |
| `docs.page` | `id` | `{ page: DocPage }` |
| `docs.search` | `query`, `kind?`, `limit?` (по умолчанию 30, максимум 100) | `{ query, hits: DocSearchHit[] }` |
| `docs.outdated` | `limit?` (по умолчанию 50, максимум 500) | `{ items: DocOutdatedItem[] }` |
| `docs.save` | `id`, `summary`, `details?`, `cases?` | `{ page: DocPage \| null }` |
| `docs.remove` | `id` | `{ page: DocPage }` |

`section` и `kind` принимают одно из значений: `module`, `procedure`, `function`, `variable`.

Методы чтения сами проверяют, не появился ли новый коммит (не чаще раза в 3 секунды), и при необходимости запускают переиндексацию в фоне. Ответ при этом не ждёт окончания индексации и возвращает текущие данные. Вызывать `docs.sync` перед каждым запросом не нужно.

### docs.tree

Возвращает только прямых потомков узла. Корень раздела запрашивается с пустым `node`:

```json
{"method": "docs.tree", "params": {"section": "function"}}
```

```json
{
  "section": "function",
  "node": "",
  "items": [
    {"id": "src/CommonModules", "label": "Общие модули", "type": "folder", "count": 1, "hasChildren": true, "documented": false, "stale": false}
  ],
  "syncing": false
}
```

Раскрытие узла:

```json
{"method": "docs.tree", "params": {"section": "function", "node": "src/CommonModules/Остатки/Module.bsl"}}
```

```json
{
  "section": "function",
  "node": "src/CommonModules/Остатки/Module.bsl",
  "items": [
    {
      "id": "src/CommonModules/Остатки/Module.bsl#ПолучитьОстаток",
      "label": "ПолучитьОстаток",
      "type": "symbol",
      "kind": "function",
      "docId": "src/CommonModules/Остатки/Module.bsl#ПолучитьОстаток",
      "count": 0,
      "hasChildren": false,
      "isExport": true,
      "documented": false,
      "stale": false
    }
  ],
  "syncing": false
}
```

`DocTreeNode`:

| Поле | Значение |
|---|---|
| `id` | Что передать в `node`, чтобы раскрыть узел |
| `label` | Подпись: «Документы», «Заказ», «Модуль объекта», «ОбработкаПроведения» |
| `type` | `folder`, `module` или `symbol` |
| `kind` | Для модуля `module`, для символа вид символа |
| `docId` | Есть у `module` и `symbol`: открыть страницу через `docs.page` |
| `count` | Сколько элементов раздела внутри (для бейджа) |
| `hasChildren` | Показывать ли стрелку раскрытия |
| `isExport` | Только у символа: метод или переменная с `Экспорт` |
| `documented` | Для символа — есть описание. Для папки и модуля — описано всё внутри |
| `stale` | Есть устаревшее описание (код изменился после того, как его написали) |

В разделе «Модули» модуль — лист дерева (`hasChildren: false`): клик открывает страницу модуля, а его методы показаны на самой странице. В остальных разделах модуль раскрывается в список символов этого вида.

Общие модули, формы и команды сворачиваются: вместо «Остатки → Модуль» в дереве один узел «Остатки».

### docs.page

```json
{
  "page": {
    "id": "src/CommonModules/Остатки/Module.bsl#ПолучитьОстаток",
    "kind": "function",
    "title": "ПолучитьОстаток",
    "path": "src/CommonModules/Остатки/Module.bsl",
    "breadcrumbs": ["Общие модули", "Остатки", "Модуль", "ПолучитьОстаток"],
    "module": {"id": "src/CommonModules/Остатки/Module.bsl", "title": "ОбщийМодуль.Остатки"},
    "signature": "Функция ПолучитьОстаток(Номенклатура, Знач Склад = Неопределено) Экспорт",
    "isExport": true,
    "directive": "&НаСервере",
    "region": "ПрограммныйИнтерфейс",
    "line": 7,
    "endLine": 9,
    "parameters": [
      {"name": "Номенклатура", "byValue": false},
      {"name": "Склад", "byValue": true, "defaultValue": "Неопределено"}
    ],
    "comment": "Возвращает остаток товара на складе.",
    "calls": ["РассчитатьОстаток"],
    "note": {
      "summary": "Свободный остаток с учетом резервов.",
      "details": "Читает регистр **ТоварыНаСкладах**.",
      "cases": [{"title": "Склад не указан", "text": "Суммирует по всем складам."}],
      "author": "user",
      "updatedAt": "2026-10-15T19:22:38.221Z",
      "stale": false
    },
    "members": [],
    "revision": "69d8b7ff9852ce38ff52114438d324232ed15753"
  }
}
```

`DocPage`:

| Поле | Значение |
|---|---|
| `kind`, `title` | Вид и заголовок. У модуля заголовок вида «Документ.Заказ: Модуль объекта» |
| `path`, `line`, `endLine` | Файл и строки в рабочем каталоге агента, для перехода к коду |
| `breadcrumbs` | Путь для строки навигации над заголовком |
| `module` | Только у символа: ссылка на страницу модуля |
| `signature`, `directive`, `region`, `isExport` | Только у символа. `directive` и `region` могут отсутствовать |
| `parameters` | Параметры метода, у модуля и переменной пустой список |
| `comment` | Комментарий над методом в коде (BSLDoc) или шапка модуля. Может отсутствовать |
| `calls` | Какие методы вызываются внутри (по имени) |
| `note` | Описание из документации. Нет поля — описания ещё нет |
| `note.details`, `note.cases[].text` | Markdown, рендерите через `P.markdown` |
| `note.author` | `agent` или `user` |
| `note.stale` | `true` — код изменился после того, как описание написали |
| `members` | Только у модуля: все символы в порядке строк, с `summary`, `documented`, `stale` |
| `revision` | Коммит, по которому построен индекс |

### docs.search

Сначала ищет по имени (часть имени, регистр не важен), затем по тексту комментариев и описаний.

```json
{"method": "docs.search", "params": {"query": "остат", "limit": 30}}
```

```json
{
  "query": "остат",
  "hits": [
    {
      "id": "src/CommonModules/Остатки/Module.bsl#ПолучитьОстаток",
      "kind": "function",
      "title": "ПолучитьОстаток",
      "moduleTitle": "ОбщийМодуль.Остатки",
      "path": "src/CommonModules/Остатки/Module.bsl",
      "snippet": "Свободный остаток с учетом резервов.",
      "documented": true
    }
  ]
}
```

При совпадении по тексту в `snippet` найденные слова обёрнуты в `«…»`. Подсвечивайте их после `P.escape`, не через `innerHTML` сырого текста.

### docs.outdated

Записи для вкладки «Требуют внимания»:

```json
{"items": [{"id": "src/…/Module.bsl#НоваяПроцедура", "kind": "procedure", "title": "НоваяПроцедура", "moduleTitle": "ОбщийМодуль.Остатки", "path": "src/…/Module.bsl", "reason": "new"}]}
```

`reason`: `new` — появился в новом коммите и не описан, `changed` — изменился и не описан, `stale` — описание устарело. При первой индексации ничего не помечается, иначе в ERP «требовали бы внимания» десятки тысяч методов.

### docs.save и docs.remove

```json
{"method": "docs.save", "params": {"id": "src/…/Module.bsl#ПолучитьОстаток", "summary": "Свободный остаток с учетом резервов.", "details": "Markdown", "cases": [{"title": "Склад не указан", "text": "Суммирует по всем складам."}]}}
```

- `summary` обязателен и не может быть пустым.
- `cases` с пустыми `title` и `text` отбрасываются.
- Сохранение заменяет описание целиком. Отправляйте все поля, а не только изменённые.
- После сохранения `note.author` становится `user`, `note.stale` сбрасывается.
- Ответ `page: null` означает, что описание сохранено для кода, которого ещё нет в последнем коммите. Страница появится после коммита.

`docs.remove` удаляет описание и возвращает страницу без `note`.

### docs.status и docs.sync

`DocsStatus`:

```json
{
  "root": "/home/user/ws/Trade",
  "source": "git",
  "revision": "69d8b7ff…",
  "syncedAt": "2026-10-15T19:22:38.216Z",
  "syncing": false,
  "progress": null,
  "lastError": null,
  "modules": 2,
  "symbols": 2,
  "documented": 1,
  "stale": 0,
  "outdated": 0
}
```

- `source`: `git` (последний коммит) или `worktree` (проект не под git, читаются файлы рабочего каталога).
- `revision: null` — проект ещё ни разу не индексировался.
- `syncing` и `progress: {done, total}` — идёт переиндексация, в этот момент можно показать полосу прогресса.
- `lastError` — текст последней ошибки индексации.

`DocsSyncReport`: `{ revision, added, changed, removed, upToDate, durationMs }`.

## Прогресс индексации

Во время индексации ПерУН вызывает `ctx.ui.setStatus("1c-docs", …)`. Плагин уже переводит это в `ChatEvent.StatusChanged`, а страница получает событие `status`:

- `Документация: индексация 120/15000` — идёт индексация;
- `Документация: 69d8b7ff` — готово, индекс на этом коммите;
- `Документация: ошибка синхронизации` — подробности в `docs.status` → `lastError`.

Если экран документации открыт, то при переходе статуса из «индексация …» в любой другой перезапросите раскрытые узлы и открытую страницу. Другой обработки не нужно.

## Интерфейс

### Кнопка в шапке

`header.js`: между «Историей» и «Новым чатом» добавить `P.iconButton("explain", "Документация", …)`. Иконка книги `explain` уже есть в `icons.js`. Кнопка открывает и закрывает экран документации. Скрыта, если в `get_commands` нет `docs`.

### Экран

Откройте экран поверх `#chat` и `#composer`, а не в отдельной вкладке EDT: так он работает на том же мосте и в тех же стилях. Шапка остаётся, кнопка «Документация» в ней подсвечена. Закрытие — та же кнопка или `Esc`.

```
┌ шапка ───────────────────────────────────────────────┐
├─────────────────────┬────────────────────────────────┤
│ [ поиск…          ] │ Общие модули › Остатки › Модуль │
│ Модули Процедуры    │ ПолучитьОстаток   Экспорт       │
│ Функции Переменные  │ &НаСервере                      │
│ Требуют внимания 3  │ Функция ПолучитьОстаток(…)      │
│                     │ [Открыть в коде] [Изменить]     │
│ ▾ Общие модули   12 │                                 │
│   ▾ Остатки       3 │ Описание                        │
│     • Получить… ✓   │ Свободный остаток с учетом…     │
│     • Сбросить…  ⚠  │ Частные случаи                  │
│ ▸ Документы      40 │ ▸ Склад не указан               │
└─────────────────────┴────────────────────────────────┘
```

На ширине до 640 px показывайте одну колонку: дерево или страницу. На странице кнопка «← К списку» возвращает к дереву, состояние дерева при этом сохраняется.

### Сайдбар

- **Вкладки разделов** — `section` для `docs.tree`. При первом открытии вкладки запрашивается корень, раскрытие узла запрашивает его детей. Загруженных детей кэшируйте до события «индексация завершена».
- **Узел:** стрелка, если `hasChildren`; подпись `label`; справа `count` для папок и модулей. У символа метка `Экспорт` (`isExport`), зелёная точка при `documented`, жёлтый значок при `stale`.
- **Клик:** папка раскрывается; модуль или символ раскрывается (если есть дети) и открывает страницу по `docId`.
- **«Требуют внимания»** — плоский список из `docs.outdated` с причиной (`new` — «новый», `changed` — «изменён», `stale` — «устарело»). Над списком кнопка «Описать с ПерУН»: она отправляет в чат `/docs update` и закрывает экран, чтобы был виден ход работы.
- **Поиск:** запрос через 250 мс после последнего нажатия, от 2 символов, `docs.search` с `limit: 30`. Пока строка поиска не пуста, вместо дерева показывается список результатов: заголовок, `moduleTitle` серым, `snippet`. Фильтр по виду — текущая вкладка (`kind`), во вкладке «Требуют внимания» ищите без фильтра. Esc в строке поиска очищает её.

### Страница

1. Хлебные крошки `breadcrumbs`. У символа последний элемент совпадает с заголовком, предпоследние ведут на страницу модуля (`module.id`).
2. Заголовок: `title`, метки `Экспорт`, `directive`, `region`.
3. Сигнатура моноширинным шрифтом с подсветкой `P.highlight(signature, "bsl")`.
4. Кнопки:
   - «Открыть в коде» — открыть `path` в редакторе EDT на строке `line`;
   - «Изменить» — режим редактирования;
   - «Спросить ПерУН» — закрыть экран и отправить в чат «Объясни, что делает `<title>` (`<id>`), и обнови документацию».
5. Плашка при `note.stale`: «Код изменился после того, как писалось описание. Проверьте его или попросите ПерУН обновить».
6. «Описание» — `note.summary` абзацем, `note.details` через `P.markdown`. Подпись: «агент» или «вы» (`note.author`) и `P.relativeTime(Date.parse(note.updatedAt))`. Нет `note` — заглушка «Описания пока нет» и кнопка «Спросить ПерУН».
7. «Частные случаи» — раскрывающиеся блоки: заголовок `title`, тело `text` через `P.markdown`.
8. «Параметры» — таблица: имя, `Знач`, значение по умолчанию.
9. «Комментарий в коде» — `comment` как преформатированный текст.
10. «Вызывает» — `calls` чипами. Клик ищет имя через `docs.search`.
11. У модуля — «Состав модуля»: `members` списком, клик открывает страницу символа.

### Редактирование

- Поля: «Кратко» (`summary`, обязательное, textarea на 2–3 строки), «Подробно» (`details`, Markdown), «Частные случаи» (список пар «условие» и «что происходит», с кнопками «+ Добавить» и удалением).
- «Сохранить» → `docs.save` со всеми полями. «Отмена» возвращает просмотр. «Удалить описание» → `docs.remove` с подтверждением.
- Пока запрос идёт, кнопки неактивны. Ошибку покажите тостом `P.toast("error", …)`.
- Последнее сохранение побеждает: если описание параллельно поменял агент, оно перезапишется. Блокировки не нужны.

## Изменения в коде плагина

Раскладка повторяет существующие слои.

**domain** — record-ы ответов: `DocTreeNode`, `DocPage`, `DocNote`, `DocCase`, `DocMember`, `DocSearchHit`, `DocOutdatedItem`, `DocsStatus`. Можно не типизировать каждое поле: если страница только отображает данные, допустимо передавать `JsonObject` от RPC прямо в `EventSerializer`. Нужен только `DocNoteDraft(summary, details, cases)` для сохранения.

**application/port** — новый порт:

```java
public interface DocsGateway {
    CompletableFuture<JsonObject> call(String method, JsonObject params);
}
```

`AgentGateway.docs()` возвращает его, как сейчас `tools()` возвращает `SessionTools`.

**application** — `DocsService`: вызывает порт и превращает ответы в события `ChatEvent`. Как `ChatService`, ошибки он отдаёт через `ChatEvent.Notice("error", ErrorText.describe(e))`.

**domain/ChatEvent** — новые события:

```java
record DocsLoaded(String kind, String requestKey, JsonObject data) implements ChatEvent {}
```

`kind` — `tree`, `page`, `search`, `outdated`, `status`, `saved`. `requestKey` — `section + "|" + node` для дерева, `id` для страницы, `query` для поиска. По нему страница отбрасывает устаревшие ответы: например, ответ на старый поисковый запрос, пришедший после нового.

**infrastructure/rpc** — `RpcDocsGateway`:

```java
JsonObject payload = new JsonObject();
payload.addProperty("method", method);
payload.add("params", params == null ? new JsonObject() : params);
return rpc.get().request("extension_request", payload, !"docs.sync".equals(method));
```

Поддержка документации определяется в `PerunGateway.start()` рядом с `RpcStateAssembler.supportsModes(commands)`: есть ли команда `docs`. Флаг уходит в `AgentState` (`docsSupported`) и в `JsonViews.state`.

**infrastructure/mock** — `MockDocsGateway` с парой модулей для демо-режима, чтобы экран можно было открыть без агента.

**ui/bridge**:

- `WebCommandRouter`: действия `docsTree {section, node}`, `docsPage {id}`, `docsSearch {query, kind}`, `docsOutdated`, `docsSave {id, summary, details, cases}`, `docsRemove {id}`, `docsSync`, `docsOpenSource {path, line}`. Последнее не уходит в агент: файл открывается в редакторе EDT через `IDE.openEditor` и `ITextEditor.selectAndReveal` (путь `path` относительно `spec.workDirectory()`).
- `EventSerializer`: `DocsLoaded` → `{"type": "docs", "kind": …, "key": …, "data": …}`.
- `PageAssembler`: добавить `docs.css` в `STYLES` и `docs.js` в `SCRIPTS` перед `header.js`.

**web** — `js/docs.js` (модуль `P.docs` с `open()`, `close()`, `isOpen()` и обработчиком `P.on("docs", …)`) и `css/docs.css` на существующих токенах `tokens.css`. Если файл выходит за 200 строк, разбейте его: `docs-tree.js`, `docs-page.js`, `docs-editor.js`.

Обмен страницы с Java:

| Страница → Java (`P.post`) | Java → страница (`P.on("docs")`) |
|---|---|
| `docsTree {section, node}` | `{kind: "tree", key: "function\|src/CommonModules", data: {items, syncing}}` |
| `docsPage {id}` | `{kind: "page", key: id, data: {page}}` |
| `docsSearch {query, kind}` | `{kind: "search", key: query, data: {hits}}` |
| `docsOutdated` | `{kind: "outdated", key: "", data: {items}}` |
| `docsSave {…}` / `docsRemove {id}` | `{kind: "saved", key: id, data: {page}}` |
| `docsSync` | `{kind: "status", key: "", data: {report, status}}` |

Ошибки приходят обычным `notice` с `level: "error"`.

## Крайние случаи

| Ситуация | Что делать |
|---|---|
| `status.revision == null` и идёт индексация | В дереве «Строим документацию по коду проекта…» и прогресс из `progress` |
| Проект не под git (`source: "worktree"`) | Работает так же. Строка в подвале экрана: «Источник: файлы проекта (git не найден)» |
| `docs.page` вернул ошибку «не найдена» | Метод удалили в новом коммите: закрыть страницу и перезапросить раскрытые узлы |
| `docs.save` вернул `page: null` | Тост «Описание сохранено, появится после коммита» |
| Агент перезапустился (`connected`) | Сбросить кэш дерева и перезапросить открытое |
| Пустой раздел (например, нет переменных) | «В проекте нет переменных модулей» |

## Как проверить

1. Открыть проект EDT под git с хотя бы одним коммитом.
2. Нажать «Документация». После индексации в «Функциях» видны общие модули и их функции.
3. Спросить в чате «Что делает функция X?». Агент ответит и сохранит описание (`1c_docs_write`), оно появится на странице X.
4. Отредактировать описание на странице и сохранить. В новом чате спросить про X: агент опирается на сохранённое описание (виден вызов `1c_docs_read` или `1c_docs_search`).
5. Изменить тело X и закоммитить. Страница X показывает «устарело», X есть во вкладке «Требуют внимания».
6. «Описать с ПерУН» запускает `/docs update`, и после ответа агента пометка «устарело» пропадает.
