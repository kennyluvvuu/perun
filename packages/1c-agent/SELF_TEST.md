# Самопроверка ПерУН

Документ описывает, как проверить, что ПерУН доводит задачу в проекте 1C:EDT до конца: понимает метаданные, правильно создаёт и меняет `.mdo`, пишет код, собирает конфигурацию в базу и не уходит в обходные пути.

Есть два способа проверки: автоматический eval и ручной прогон по сценарию.

---

## 1. Автоматическая проверка (eval)

Eval `packages/evals/evals/onec-feature.eval.ts` создаёт маленький EDT-проект со справочником «Товары» и просит агента добавить регистр накопления и документ с проведением. Проверка считается пройденной, если:

- все `.mdo` проекта проходят проверку структуры без замечаний;
- созданы регистр `ОстаткиТоваров` и документ `ПоступлениеТоваров`;
- в модуле объекта документа есть `ОбработкаПроведения` с движениями по регистру;
- агент пользовался инструментом `1c_md`.

Запуск (нужен ключ выбранной модели):

```bash
PI_PROVIDER=<провайдер> PI_MODEL=<модель> npm run eval:host --workspace=@earendil-works/pi-evals -- onec-feature
```

В отчёте eval видно число шагов и токенов: сравнивайте их между версиями промпта.

---

## 2. Ручной прогон

Подготовка:

1. Откройте ПерУН в каталоге с EDT-проектом (где есть `src/Configuration/Configuration.mdo`).
2. Режим `НАПИСАТЬ` (`/mode write`), права `/permission auto-approve`.
3. Для шагов 5–6 нужны платформа 1С (ibcmd или 1cv8) и 1C:EDT CLI. Без них эти шаги отмечаются как «не применимо».

| № | Запрос пользователю агента | Ожидаемое поведение | Признак провала |
|---|---|---|---|
| 1 | «Опиши документ <Документ> и регистр <Регистр>: реквизиты, ТЧ, движения, типы» | `1c_md info` для каждого объекта, ответ с типами и путями | чтение `.mdo` целиком, поиск скриптов, выдуманные реквизиты |
| 2 | «Добавь регистр накопления ОстаткиТоваров и документ ПоступлениеТоваров с ТЧ Товары; при проведении — приход по регистру» | `1c_md create` (регистр, затем документ с `registerRecords`), правка `ObjectModule.bsl`, `1c_md validate` без замечаний | копирование чужого `.mdo`, ручное создание XML, файлы в `Ext/` |
| 3 | «Добавь в документ реквизит Комментарий (строка без ограничения) и колонку Цена в ТЧ Товары» | `1c_md add` (в том числе с `tabularSection`) | дубли имён, сломанный порядок или uuid |
| 4 | Испортите `.mdo` вручную (например, тип `CatalogRef.Нет`) и попросите «почини метаданные» | агент видит замечания проверки `.mdo` и исправляет файл | правка «наугад» без проверки |
| 5 | «Собери конфигурацию в базу и исправь ошибки» | `1c_ib status`, `1c_ib build`; ошибки платформы приходят с путями `src/…:строка` и исправляются | поиск платформы через `which`/`find /`, повтор одной и той же команды |
| 6 | «Открой базу, хочу посмотреть документ» | `1c_ib run` | попытка запуска 1С через bash |
