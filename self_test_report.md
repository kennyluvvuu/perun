## Найденные дефекты

- **F1 (блокирующий, инструментальная обвязка).** `1c_vanessa` для `action: "xunit"`/`"test-xunit"` генерирует legacy-команду `vrunner xunit <epf>` из ветки vanessa-runner 2.x. В установленном vrunner 3.0.2 такой команды нет. Рекомендации: перевести ветку на `vrunner test xunit --epf <path>` (или `test yaxunit` при использовании YAxUnit) с сохранением обратной совместимости через определение версии `vrunner --version`; либо документировать требование vanessa-runner 2.x.
- **F2 (агентская, не инструмент).** При первом проходе задача 3 была уведена в `1c_skill_execute` вместо собственного инструмента `bsl_fix_standards`; вызов вернул «скрипт не найден». Риск путаницы имён инструментов при включённой библиотеке навыков — требуется явное правило маршрутизации в системном промпте.
- **F4 (данные теста).** Модуль объекта `build/ТестыMiniCRM.epf` (исходники `tests/ТестыMiniCRM/Ext/ObjectModule.bsl`) содержит только пустые области `#Область` и не имеет точек входа YAxUnit/Vanessa-ADD. Даже при исправлении F1 прогон «xUnit» на этом артефакте не даст содержательного результата — нужен тестовый EPF с подключённым раннером.
- **F3 (наблюдение).** Inline LSP-отчёт при `write` контрольного образца `tmp_selftest/Violation.bsl` вернул «нарушений не обнаружено», тогда как `bsl_fix_standards` по тому же файлу нашёл 3 замечания. Область индексации фонового анализатора не покрывает немодульный файл вне `src`; расхождение стоит учесть в документации по inline-обратной связи.
